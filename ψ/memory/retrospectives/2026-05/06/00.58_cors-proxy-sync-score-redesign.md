## Key Code Changes

- **CORS proxy**: Instead of browser fetching `docs.google.com` and `script.google.com` directly (which 302 redirect and fail CORS), the app now calls `/api/fetch-sheet` and `/api/sync-scores` which are Cloudflare Pages Functions that follow redirects server-side
- **Grade system**: Expanded from 5 grades (V/SG/G/B/M) to 13 (V/V-/SG+/SG/SG-/G+/G/G-/B+/B/B-/M+/M-) with derived percentages from the 5 base settings values
- **Leaderboard**: Each row is ~52px tall, shows rank badge + dog name + score. Tap expands to show VP breakdown + edit/delete. Top 3 get gradient badges

## Architecture Decisions

1. **Cloudflare-only deployment**: Removed Vercel entirely. Rate limits and framework detection issues made it unreliable. Cloudflare Pages + Functions works out of the box.
2. **Server-side proxy over CORS headers**: Adding proxy functions is simpler than trying to make Google's 302 redirects work with browser CORS. The proxy follows redirects and returns data with `Access-Control-Allow-Origin: *`.
3. **Derived grade percentages**: Instead of adding 8 new settings fields, sub-levels are derived from the 5 base grade percentages (e.g., `V- = gradeV - 4`). This keeps the settings page simple while supporting fine-grained scoring.

## Lessons Learned

- When Google endpoints return 302 redirects, browsers can't follow them cross-origin even if the final response has CORS headers. Always use a server-side proxy for Google Sheets/Apps Script from browser apps.
- Always verify endpoints from the browser's perspective (CORS), not just from server-side tools like Python's urllib.
