## AI Diary

This was one of the most satisfying migrations I've done because the parallel agent strategy worked almost perfectly. Four agents writing to non-overlapping file paths meant zero file conflicts. The biggest risk was API surface mismatches between agents — Agent C built JudgeTab expecting a certain `saveScore` signature from Agent A's useScores hook, and they independently converged on compatible interfaces. That said, I got lucky. The App.tsx wiring phase exposed a real problem: agents built components that read entirely from context (no props), while I wrote App.tsx passing props to them. Had to strip all props from App.tsx. This isn't a failure of the agents — it's a failure of my specification. I told agents to "read from useApp()" but then wrote the orchestrator assuming prop-based interfaces. Inconsistent specification, caught late.

The Vite 8 `manualChunks` issue was a small but instructive blocker. Vite 8 switched to Rolldown which requires `manualChunks` as a function, not an object. The plan assumed Rollup-style config. Minor but caused a failed build on first try.

The rebase conflict on .gitignore was noise — someone pushed a Cloudflare Workers config while we were working. Resolved trivially.

## Honest Feedback

1. **Specification inconsistency between agent prompts and App.tsx wiring.** I told all agents to use `useApp()` context directly, then wrote App.tsx as if components accepted props. This caused 6+ type errors that I had to fix manually. Should have either specified prop-based interfaces OR written App.tsx first as a skeleton for agents to conform to. The fix was simple (remove all props) but the pattern reveals a coordination gap.

2. **No runtime verification before push.** The build compiles and TypeScript checks pass, but I never actually opened the browser to verify the app renders correctly. The dev server was running but I didn't visually confirm registration, scoring, leaderboard flows work. This is a real risk — type safety doesn't guarantee functional correctness.

3. **Agent overlap on utility files.** Both Agent A and Agent D wrote `constants.ts` and `exportCsv.ts`. Agent D also wrote `Modal.tsx` which Agent B already created. These overwrites were harmless (same content) but indicate I should have given agents stricter file ownership boundaries.

## Lessons Learned

- Parallel agents with non-overlapping file paths work well for large migrations. 4 agents completed in ~30 min what would take ~90 min sequentially.
- Always write the orchestrator (App.tsx) BEFORE spawning agents, or at minimum specify the exact interface boundary (props vs context) in every agent prompt.
- Vite 8 uses Rolldown — `manualChunks` must be a function, not an object.
- `tsc --noEmit` passing is necessary but not sufficient. Runtime testing is still required.
